### A2UI 1.0 by Google
**Link:** https://developers.googleblog.com/a2ui-10-build-delightful-fast-reliable-agentic-experiences · released **11 November 2026** · spec: https://a2ui.org/specification/v1.0-a2ui/ · repo: https://github.com/a2ui-project/a2ui · Show HN thread: https://news.ycombinator.com/item?id=50461919
**Type:** Tool (open protocol)
**What it is:** A2UI is Google's open protocol for *generative UI*, and 1.0 is its first stable release. The agent does not write markup or CSS; it describes what should appear, and the host application draws it with its own native components — "Native to your brand. Agents use your design system and nothing else. They place and configure only the components you register." It ships open-source renderers for React (`@a2ui/react`), Angular and Lit on the web, Flutter for mobile/desktop, SwiftUI on iOS, with Jetpack Compose still at 0.9.1; agent SDKs for Python, TypeScript and Dart. 1.0 adds **bidirectional function calls** (a form field can call a function on the agent — verify a provider ID, check availability — and the result lands back in that component), accessibility support, and extension metadata. The web and Flutter renderers also run inside **MCP Apps**, so the same screens can appear in Claude or Gemini.

**What's good about it:** The sentence about the catalog is the most important design sentence published this week, and it is important because it is a *constraint*, not a capability. Every other agent-UI story in 2026 has the model producing markup, which means the model's taste — the rounded corners, the purple gradient, the letter-spacing that is almost right — arrives with the output. A2UI inverts the ownership: you enumerate the components and their allowed configuration, and the agent's freedom is bounded by your library. That is the same principle this brief has been arguing in aesthetic terms for months, arriving as a wire format. Two other decisions deserve respect. First, **values never reach the model** — data binding happens server-side, so sensitive values are filled in by the app rather than generated by the agent, which for a hospital is a compliance feature wearing a design feature's clothes. Second, the protocol is designed to run with **no LLM at all** in some paths (declarative UI, "system one" decision models that pick components, A2UI Express), which means a fast, cheap, deterministic renderer and a frontier model can produce the same compliant screen. And the renderers are open source and cover the platforms a department actually has.

**Pros:**
- The catalog is a hard boundary, not a prompt instruction: an agent cannot invent a fifth button style because the renderer will not have one.
- Stable 1.0 with real renderers (React, Angular, Lit, Flutter, SwiftUI) and three agent SDKs — usable today, not a roadmap.
- Bidirectional function calls make an agent-built form *functional* rather than decorative: a picker can verify a provider ID in place.
- Server-side binding means the model composes structure and never sees the patient data — the architecture a health system needs before it lets an agent build a screen.
- Works inside MCP Apps, so the identical surface can appear inside Claude or Gemini without a second implementation.

**Cons:**
- It is an engineering protocol with essentially **no design-side tooling**: no Figma plugin, no visual catalog editor, no way for a designer to author the catalog without writing it.
- The spec page still carries a "Last Updated: Jun 8, 2026" stamp while the blog announces 11 November — one small sign that the documentation is trailing the launch.
- Compose is at 0.9.1, ByteDance's Lynx renderer is still being adapted from 0.9, and the "already building" list (Atlassian, Alation, Bloomberg, ByteDance) is Google's claim with one worked example.
- A catalog renders a mediocre design system exactly as faithfully and exactly as fast as a good one. The protocol raises the floor; it does nothing for the ceiling.

**Should we...**
- ✅ **Adopt it** — use it now; it raises our design ceiling
**Why:** Adopt the *catalog*, this week, before adopting a single SDK. The Unified Platform's exposure is not that an agent will draw the wrong purple; it is that the rules of the platform live in three places that can disagree — tokens in code, the Figma file, and whatever gets pasted into a prompt. A2UI's answer is a page of writing: the closed list of components, the states each may occupy, and the configuration each accepts. Written properly for this platform, that page says: 13px table rows with tabular figures, one accent and never a second, the radius scale, the four status colours, and the empty/error/loading state that every list must be able to show. That is a day's work and it is the difference between an agent that composes screens and an agent that generates interfaces. The same manifest applies to the Chapter Player — a player has maybe nine components (cover, chapter row, scrubber, speed control, bookmark, sleep timer, download state, error, empty) and once they are enumerated, no future agent work can restyle the player by accident. And for client-style sites, A2UI gives the correct brief: the site reads as premium only if the components are premium and the set is closed, which is the opposite of "make it beautiful." Where to be careful is the same place as always — a protocol cannot tell you the crop is boring or the photograph is the wrong photograph. It only guarantees that the boring crop will be perfectly rounded.

### Palermo by Profound
**Link:** https://palermo.tryprofound.com/ · docs: https://palermo.tryprofound.com/docs/get-started · tokens: https://palermo.tryprofound.com/docs/colors · surfaced on X by @dbabbs, **11 November 2026**
**Type:** Idea (with a tool's documentation)
**What it is:** Palermo is the design system behind Profound's products — tokens, forty-odd React/TypeScript components, icons, colour, typography and guidelines — published as a **public documentation site** with a deliberate refusal attached: "Palermo is the design system behind Profound's products. It lives inside our codebase and isn't published as a package. … The only way to install Palermo is to work at Profound." So the site is simultaneously the internal reference the team works from, an argument about how the company approaches design, and a recruiting page.

**What's good about it:** The publishing decision *is* the design decision, and it is the one worth stealing. A design system that only exists inside a product cannot be judged, cannot be cited, and cannot be audited — and nobody outside ever learns that the work was done. Publishing it converts documentation into evidence. Then the token architecture, which is unusually disciplined for a startup: the names are **semantic layers** — `bg-*` for surfaces, `fill-*` for solid fills, `control-*` for interactive surfaces, `text-*`, `stroke-*`, `shadow-*`, `workflow-*` — each with light and dark values side by side. The UI is near-monochrome (`#18181a` on `#ffffff`, dark `#1e1e1e`), one brand blue `#376CFF`, and the status colours are quarantined into 10%-alpha tints (`#ff5f571a`, `#15b4621a`, `#f4a4621a`) so a table full of alerts doesn't turn into confetti. The shadow system is specified as *behaviour*, not decoration: "Each regular shadow includes its border. Do not add a separate neutral border or ring" — hover adds a solid edge, focus keeps the depth and adds a 3px halo, high has no interaction states. That single paragraph is what stops the slow drift into every card having a border *and* a shadow *and* a ring. The type scale is named by role and size (`text-title-regular`, `text-title-small`, `text-title-mini`, `text-body-regular/small/mini/micro`) rather than by pixels, which is why a new screen can be built without a new decision.

**Pros:**
- Token taxonomy that separates surface from fill from control from text — the structure that makes a real dark mode possible without a second design.
- One accent, with status colours restricted to low-alpha tints. This is the discipline the Unified Platform already preaches and has never written down this cleanly.
- Shadow states specified as interaction behaviour, including the "do not add a border" rule — an enforcement sentence, not a mood.
- Type scale named by role, so a screen assembled by someone who is not a designer still lands on the right step.
- The public site doubles as a hiring and credibility surface, which is a business argument for design documentation that a hospital can actually use.

**Cons:**
- It is a marketing asset as much as a design system: no install, no licence, no contribution path, no changelog — you cannot verify the craft beyond the doc site.
- The component index is long (Active Bar through Video Player) but the hard states are not documented on the pages I could read — no coverage of empty, error, partial-load or long-content behaviour.
- The neutral-plus-one-blue look is the house style of every AI-startup product in 2026. It reads premium and it reads familiar, which are not the same thing.
- Documentation at this standard is a maintenance commitment; a two-person communications office that publishes it and then stops updating it is worse off than one that never published.

**Should we...**
- ✅ **Adopt it** — use it now; it raises our design ceiling
**Why:** Adopt the publication, not the palette. The Unified Platform has a real design system — one accent, a radius scale, a type ramp, SVG icons, a dark theme that actually works — and almost nobody outside the department knows it exists. That means the best design work in the building is invisible to the people it should be persuading: applicants deciding between programs, residents deciding whether to stay, other departments deciding whether to copy it, and leadership deciding whether design is a line item. A public, read-only reference site costs a weekend: one page per component, states included, tokens printed as tokens, a short "why this and not that" on each decision. The act of writing it will expose the gaps faster than any audit — the components that only exist in one state, the spacing values that were never rationalised, the icon set that has three line weights. It also answers the recruitment question in the most direct way available: a urology program with documented interface standards reads as an institution that has its act together, which is precisely what a Sub-I is trying to determine. Copy the token taxonomy as well — `bg`/`fill`/`control`/`text` is a better split than the platform's current naming and it is the thing that will let a dark Chapter Player and a light marketing site share one source. What not to copy is the near-black-and-blue; that is Profound's, and by now it is also everybody's.

### "AI fonts" — the typeface as tell
**Link:** https://tech.yahoo.com/ai/article/first-it-was-em-dashes-now-fonts-are-making-people-suspicious-of-ai-184955533.html · published **10 November 2026** · Yahoo Tech
**Type:** Idea
**What it is:** A report on the newest AI tell: not fingers, not em dashes — **fonts**. An indie author, T.M. Kirk, was accused of using AI in an online post because of her typeface choice: "Even though it wasn't even flagged as AI, I was told I shouldn't have used a certain font. That it was my fault for making it 'look like' AI." The piece then explains the mechanism properly: models do not select fonts, they **arrange pixels** based on training data, so output converges on an average of the millions of ads, posters and banners in the corpus — most often "writing that resembles the Inter font," and more recently imitations of the display face **Road Rage** for dramatic flyers. Because the lettering is pixel-shaped rather than typeset, the spacing and consistency are subtly wrong, which is the uncanny quality people are reacting to. Designers, it reports, have started avoiding certain typefaces pre-emptively.

**What's good about it:** It replaces a vibe with a diagnosis. The reason AI lettering looks *off* is not that the model chose badly — it is that the model never chose at all, and the artefacts of pixel-averaging (inconsistent sidebearings, wobbling stems, a word that is almost a word) are exactly what a trained eye reads as cheap. That is the same conclusion this brief has been reaching from the craft side, now arriving as a social fact with a named casualty. Second, it documents the migration of the tell: em dashes, then "delve," then structure, now letterforms — and it is honest that the tells will keep moving, which is the argument against building a practice around avoiding them. Third, the reporting on the cost is unusually clear-eyed: writers inserting typos to prove humanity, artists posting time-lapses and initial sketches, and time-lapses themselves now fakeable. Fourth, it cites the practitioner thread — r/graphic_design's "do you avoid certain design choices now because of AI" — so the behaviour is documented, not speculated.

**Pros:**
- A real mechanism (pixel-averaging rather than typesetting) that explains the uncanny spacing instead of just naming it.
- Names the specific faces in play — Inter-like lettering as the baseline, Road Rage as the current dramatic-flyer default — which makes the warning checkable.
- Reframes type choice as a *reputational* decision, which is the only framing that will survive contact with a communications office.
- Ends on the correct note: the tells will keep moving, so the durable answer is craft, not avoidance.

**Cons:**
- It is a trend piece built on one Instagram post and a handful of threads; there is no measurement of how often any font is actually used by any model.
- The Road Rage claim is sourced to a blog post and a single X thread, and should be read as an observation, not a finding.
- "Avoid certain fonts" is advice that expires: as models improve at rendering clean type, the stigma attached to specific faces will persist while the evidence evaporates.
- It slightly conflates two different things — typographic craft and AI detection — when a well-set page in a common face is still well-set, and a badly set page in an obscure face is still badly set.

**Should we...**
- ✅ **Adopt it** — use it now; it raises our design ceiling
**Why:** Adopt the response, and start with the uncomfortable part: the Unified Platform is set in **Inter**, which this article names as the single most common convergence point for AI-generated lettering. In product UI that remains defensible — Inter is a deliberate, legible, freely licensed system choice, and the platform's discipline (one accent, real spacing, tabular figures) is what carries it. In *marketing* it is now a liability, because the people reading a recruitment flyer or a social card have been trained by exactly this discourse to read that lettering as generated. The move is small and specific: **one licensed display face, used only for headlines, only in external work** — a face with a name, a designer and a licence, chosen for what it does to a two-word headline at 96px. Inter keeps doing UI. That is a two-line addition to the brand spec and it changes how every poster, every Sub-I cover and every interview-season card reads. Second: keep the artefacts that prove authorship — the layered file, the sketch, the real photograph of the real OR. They cost nothing, they answer an accusation a render cannot, and they are also, not coincidentally, the things that make the work better.

### Astryx by Meta
**Link:** https://github.com/meta/astryx · docs: https://astryx.atmeta.com/ · MIT · **beta** · Show HN 10 November 2026 · agent marketplace added 10 November, agent eval added 11 November
**Type:** Tool
**What it is:** An open-source design system that spent eight years inside Meta, where it became "the most-used and largest design system in the company — powering 13,000+ apps." The public release is 150+ accessible components, brand-level theming, dark mode, ready-to-ship templates and a CLI, built on React 19 and StyleX, MIT licensed, and explicitly aimed at "people and the agents working alongside them." Themes are sets of CSS custom-property overrides, so a designer can make it theirs without forking; `swizzle` ejects a component's source into your project; styling is not locked in (Tailwind, CSS modules or plain CSS can override). 7,562 commits, 333 branches, 108 tags, 49 releases, 136 contributors.

**What's good about it:** Two mechanisms are worth the read, and neither is the component library. **First, the agent skill is generated from the system, not written about it.** The Claude Code and Codex marketplace plugin added on 10 November installs one shared Astryx skill produced by `renderComputerAgentText`, and `pnpm check:agent-plugin-skill` — part of `check:repo` — **fails the build when the committed copy drifts** from the source. That is the exact fix for the current crop of hand-written "taste skills," which go stale the moment a token changes and nobody notices. **Second, they shipped an eval.** `internal/vibe-tests/eval` commits two starter apps — Astryx and shadcn/ui, each generated by its own setup — plus five pilot tasks with Playwright probes, a reference solution per arm and a deterministic grader that "proves itself with a negative control and the empty starter before it grades anything," then requires a clean typecheck, a clean build, a passing probe and no page error. A design system publishing a head-to-head eval against the most popular alternative is a genuinely new kind of claim: not "our components are nicer," but "an agent builds a working screen with ours and here is the grader." Third, the open internals are real — the building blocks are exported, and swizzle hands you the source rather than a wrapper.

**Pros:**
- The generated, drift-checked agent skill is the correct architecture: the instruction to the agent is an artefact of the design system, versioned and enforced by CI.
- A browser-graded, self-testing eval with a negative control — the first credible way to argue that a design system produces better agent-built UI.
- 150+ accessible components including the states most systems skip, at MIT, with 49 releases and 136 contributors. This will not disappear.
- Themes as CSS custom-property overrides, no styling lock-in, and swizzle for the components you need to own — the three things that make a system adoptable rather than a dependency.
- Eight years and 13,000 apps is the largest real-world sample any open design system has offered.

**Cons:**
- **Beta**, React 19 and StyleX: adopting it means adopting a styling runtime, not adding a tool. For the Unified Platform that is a migration, not an install.
- A repo with 7,562 commits and 333 branches moves daily. Pinning a version and reading changelogs is real ongoing work, and nobody in a two-person office will do it.
- The system carries Meta's product assumptions — dense, utilitarian, social-scale, high information density — which is not a hospital's tone, and theming changes colour and radius, not proportion.
- The eval is five tasks and two arms. It is a pilot with a good grader, not proof.
- The documentation is a docsite for engineers; there is no design manual, no "why this spacing," no guidance a non-designer can follow.

**Should we...**
- 👀 **Watch it** — promising, not proven yet
**Why:** Watch the library; build the two mechanisms this month. The Unified Platform's real risk is not that its pages look bad — most now look good — it is that the same rules live in three places that can disagree: tokens in code, the Figma file, and whatever gets pasted into an agent. Astryx's first mechanism is the fix and it is a weekend of work: **generate the agent instruction from the token source, commit it, and fail the check when they diverge.** That converts "the agent sometimes gets the radius wrong" into a build error, and it means the agent's brief is always the current system rather than a memory of it. The second mechanism is more valuable and harder: **five tasks, five probes, a grader.** For this platform that is the schedule table at 1280px, the call-out form, a resident profile, the reimbursements empty state, and the interview invite — each with a scripted check (does the table header wrap, is the accent the only accent, does the empty state exist, does the form keep its labels at 320px). Then any agent-built page is graded before a human ever looks at it, and Shareef gets a number instead of an opinion. Watch rather than adopt because taking the library means StyleX, React 19 and a fast-moving dependency — and because the thing worth having is the pipeline, not the components.

### eufyMake E1 — and the Design Week Awards that came back because of it
**Link:** https://www.designweek.co.uk/design-review-how-the-eufymake-e1-uv-printer-inspired-the-return-of-the-design-week-awards/ · published **12 November 2026** · Design Week · review by David Coveney
**Type:** Tool / Technique
**What it is:** A design review of a desktop UV printer that lays down textured "2.5D" prints — up to **5mm** of relief, 1440 DPI, CMYK plus white and gloss, 330×420mm bed — for **£1,599–£2,149**. The software, eufyMake Studio, will take a flat image and **use AI to derive a depth map** so that a photograph of an oil painting prints with brushstroke relief; you can also model the relief yourself in ZBrush and supply the map. The review's real story: Design Week's editor had been asking "when will the Awards come back?" and the blocker was a **£15,000 upfront trophy bill**. He used AI to develop the concept, printed test trophies on plywood, liked them, commissioned a real artist (Matt Nightingale) for the final artwork, and relaunched the awards.

**What's good about it:** The economics are the design lesson. A programme that had been cancelled by a fixed cost came back because that cost collapsed to ink and plywood — which is the kind of change that matters more to a small communications office than any new model. Second, the AI use is exactly the right shape: it derives a **depth map** from real artwork. The designer still chooses the substrate, the crop, the finish, and ultimately commissions a human artist; the model supplies a control value, not a picture. That is generation used as a parameter. Third, the reviewer publishes the arithmetic nobody else does: an A4 at 100% coverage costs **£7–£13 in ink**, flat 70p–£2.50, the print head is a **£549 consumable** replaced roughly every eight months, steel and glass need a primer wipe or the ink picks straight off, thin acrylic warps in the heat, and rotary printing is one object at a time. Fourth, the thing the review accidentally proves: **texture is hierarchy that no generated image can imitate.** A 2mm raised line on a cover, a debossed panel, a plaque you can feel — these are the moves that still separate a printed object from a screenshot of one.

**Pros:**
- Turns a fixed £15k cost into a variable one — the specific mechanism by which a small studio can afford physical craft again.
- AI used to derive a depth map from real art rather than to invent an image; the model is a parameter, not an author.
- Published cost-per-piece and consumable numbers, including the failure modes (steel without primer, thin acrylic, overhangs). This is the honesty the category usually lacks.
- Prints on wood beautifully and holds multiple objects on one bed, so short runs — twenty plaques, four A5 boards — are genuinely practical.
- The output is a physical object, which is the one thing a generated image will never be.

**Cons:**
- £1,599–£2,149 plus ink, plus a £549 head every eight months, plus a smell that "stinks up the studio." That is a shared-studio purchase, not a department one.
- The review is written by an outlet that sells affiliate links to the printer, and says so; the enthusiasm is genuine but it is not independent.
- The materials that work best (wood, coasters, phone cases) are not the materials a trophy or a plaque wants; the ones that fail are the ones a formal award would use.
- One editor's experience, one concept, no repeat runs and no client outcome data.
- The AI depth map is impressive on impasto brushwork and "a little odd" on anything with an overhang — a narrow sweet spot presented as a general capability.

**Should we...**
- 👀 **Watch it** — promising, not proven yet
**Why:** Watch the printer; adopt the technique now, because you do not need the hardware to use it. Any print shop running a UV flatbed can take a depth map and produce a textured panel, so the first move is **one sample, not one purchase**: the Sub-I welcome packet cover, with the program mark raised 1mm on a decent board, printed by a shop that already owns the machine. If it reads the way the Design Week trophies read, that is the cheapest premium upgrade available to this department — and it lands on the artefact that matters most, since the Sub-I packet is the first physical thing a candidate holds. The same treatment applies to interview-season folders and to any plaque or award the department gives, all of which currently look like laser printouts. The larger argument is the one to keep past the specific product: as generated images get cheaper by the month, the things that read as expensive are the ones with **physical consequence** — weight, texture, foil, a real photograph of a real resident. A textured print is the cheapest available version of that, and it is now inside a small studio's budget.

### Garip Studio × Güneş Ülkesi
**Link:** https://www.creativereview.co.uk/garip-studio-gunes-ulkesi-identity-turkish-childrens-arts-school/ · published **12 November 2026** · Creative Review · identity by Garip Studio; design and creative direction Bertuğ Bilgin; copy Sıla Güven; in collaboration with All Together Now
**Type:** Idea
**What it is:** A full identity for a Turkish children's arts school — ballet, music, painting and creative drama, mostly under-tens, founded 2019 — built on a **custom logotype drawn entirely by hand and arranged in a circle to read as a sun**, from the school's name, *Güneş Ülkesi*, "Land of the Sun." The lettering is not a signature at the bottom of the layout; it is the primary visual device, "informing everything from printed materials to digital communications and the school's physical spaces." Palette: bright yellow, warm orange, soft beige, with black marks introduced by context. Type: **Halyard Display by Darden Studio** as "a more restrained typographic counterpoint to the expressive lettering." Motion: individual pieces developed per discipline, using lesson animations derived from the typography to announce classes.

**What's good about it:** The structure is the transferable part, and it is rare: a wordmark that is a **composition** rather than a lockup. Because the lettering is circular, it can be cropped, rotated, repeated around a photograph, blown up until one letter fills a poster, or animated along its own curve — one asset producing a dozen layouts, which is what a small team actually needs. Second, the pairing is a decision rather than a default: hand lettering for identity, **one** named display face (Halyard Display) for information, and no third. That is the discipline that keeps an expressive identity legible. Third, the motion system is derived rather than decorative — the animations come out of the lettering's own character and are **allocated per discipline**, so ballet, music and painting each get a distinct movement instead of one generic wiggle. Fourth, the reason is stated in a sentence anyone can repeat: "The sun is one of the first things almost every child draws." An identity whose rationale survives a committee meeting is worth more than one that merely looks good in a case study.

**Pros:**
- One device doing the work of a logo, a layout system and a motion language — the highest ratio of asset to output in this week's scan.
- A named display face chosen specifically to contradict the hand lettering, rather than a second expressive face competing with it.
- Motion allocated per service line, which turns a set of one-off animations into a system.
- The concept is explainable in one sentence by a non-designer, which is the actual test of an identity in an institution.

**Cons:**
- The source is a 300-word launch notice: no budget, no outcomes, no evidence of how the lettering behaves at 16px, in UI, or in a signature block.
- Hand-drawn childlike lettering is the most imitated "warm brand" move of the last five years and is one prompt away from generic — the craft here is real, the silhouette is not defensible.
- "Land of the Sun" is a gift of a name; a urology program has no equivalent free concept, so the derivation cannot simply be copied.
- Circular wordmarks are famously difficult to set next to anything else — they fight columns, they fight captions, and they cost a lot of empty space.

**Should we...**
- 👀 **Watch it** — promising, not proven yet
**Why:** Watch the identity, steal the allocation. The mechanism worth taking into the department is **one device per discipline**: a residency has four or five recurring things — clinic, the OR, consult, the call schedule — and each currently gets a different-looking graphic made by whoever had ten minutes. Define one short motion, or one still device, for each, derived from the program's own mark or lettering, and use them to announce things: the schedule gets one movement, the OR another, interview season a third. That is how a feed starts to look art-directed instead of assembled, and it costs a template rather than a campaign. The second steal is the two-face rule — one expressive face for identity, one restrained face for information, never a third — which is the same conclusion the AI-fonts item reaches from the opposite direction, and which the platform currently violates by using one face for everything. What to leave behind is the hand-drawn register: for a children's arts school, childlike is the brief; for a surgical specialty, it reads as a craft-fair. The principle survives without the costume.

### Anvil
**Link:** https://www.tryanvil.dev/ · Show HN: https://news.ycombinator.com/item?id=50451337 · posted **11 November 2026**
**Type:** Tool
**What it is:** An AI builder that makes **flyers and websites by writing code rather than generating images**. You describe the thing in plain words; Anvil returns a design plan (one palette, one font), writes a real React/TypeScript project — the demo build is 18 files with zero type errors — fills a live preview, and publishes to a one-click URL with an optional custom domain. Projects export to GitHub. The market is explicitly small businesses in Zambia: pricing in kwacha, mobile money through Lenco, Supabase for data and sign-in, 300,000 free credits. The Show HN title is the thesis: "An AI flyer designer that generates designs with code, not images."

**What's good about it:** The architecture is this brief's argument arriving from an unexpected direction. A flyer that is code is a flyer you can edit, re-set, translate, reprint at any size and archive as text; a flyer that is an image is a dead end that costs money to reconstruct — which is exactly what the Adobe Convert-to-Text-Layers item was about on Tuesday, and what A2UI says at protocol level, and what this says at the level of a barbershop in Lusaka. Three independent arrivals at the same conclusion in one week is a signal. Second, it constrains instead of styling: **one palette and one font, checked after every build**, which is how a non-designer gets consistency without a design system. Third, it publishes its whole stack and lets you export — the opposite of a roach motel. Fourth, the market it serves is the one where "a flyer" *is* the entire brand, which forces the product to care about legibility and print rather than about vibes.

**Pros:**
- Code output means editable, printable, size-independent artefacts — the correct unit for anything that has to be re-used.
- An explicit, stated design plan per build rather than an implicit house style the user cannot see or change.
- Export to GitHub, one-click publish, bring-your-own domain: no lock-in at any layer.
- Solves a genuinely unglamorous problem (a one-page flyer for a small business) rather than a demo, and does it in a market where the alternative is Canva.

**Cons:**
- The visible output is template-grade: **Poppins throughout**, a preset "Charcoal & Ember" palette, a full-bleed Unsplash hero. That is consistency, not art direction, and it is the exact look this brief exists to escape.
- Two points on Hacker News and one developer: a product demo, not a tool with a support path or a roadmap you can rely on.
- No typographic controls at all — no tracking, no optical sizes, no grid, no baseline — so the ceiling is the preset and the ceiling is low.
- The landing page is a pitch, not a case study: no example of a flyer that was actually printed.

**Should we...**
- 👀 **Watch it** — promising, not proven yet
**Why:** Watch the product, keep the sentence. "Generates designs with code, not images" is the correct architecture and — after Tuesday's Adobe release and today's A2UI — it is now the consensus position of everyone who has thought about it. For the department it is already an argument about the recurring flyer: **one HTML/CSS template with a content file per event**, printed from the browser at a fixed size, archived as text, versioned like everything else. That single change kills the "can you send me the original file" problem, the "the JPEG is 72dpi" problem, and the "we can't change the date without rebuilding it" problem, all at once. Where Anvil fails is the part that matters most here: Poppins-everywhere with a preset palette is the literal definition of the average, and it proves that the architecture can be right while the design stays generic. A template is only as good as the typography inside it — which is why the last two items in this brief are about type, and why the answer to slop is never a better generator.

## Slop Radar
- **"One palette, one font, checked after every build" sold as design.** Anvil's own feature list is the tell: consistency is the floor, not the ceiling. Any tool that advertises uniformity as its quality claim has told you it has no opinion about type, and type is where the opinion lives. Judge a generator by what it lets you *decide*, not by what it keeps the same.
- **The hour-long design system.** Two in-window X threads follow the same shape — @mattepstein prompting Codex to "build a full UI in Figma for our new site before I sat down," @pavlikgavrik building a flat-icon-to-3D generator "for our upcoming design system" in an hour. Both are impressive and neither is a design system: no empty state, no error state, no 320px version, no contrast check, no dark mode. Ask for those four things before believing the thread.
- **Inter as the AI tell — and the trap of avoiding tells.** Designers are now choosing type by what it *doesn't* look like, which is still choosing by negation. Picking a face because it isn't the AI face produces a different average. Pick a face for what it does to a headline at 96px, then license it.
- **Accusation as a design constraint.** An indie author was accused of using AI purely on her font choice; writers are inserting typos and artists are posting time-lapses to prove humanity, and the time-lapses are now fakeable. The practical consequence is that **process documentation is part of the deliverable**: keep the layered file, the sketches and the real photograph, and say who made them. That costs nothing and it is also, not coincidentally, better practice.

## Overall Assessment
The centre of this week is the **catalog** — the enumerated list of things an agent is allowed to draw. A2UI 1.0 makes it a protocol and puts the data binding on the server; Astryx generates its agent instruction from the token source and fails the build when the two drift; Palermo publishes its catalog publicly and treats the publication as the point. Three different scales, one argument: the way to escape generic output is not a better prompt, it is a **closed set of good components plus a written rule about their states**. Meanwhile the type conversation moved from words to letterforms and became social — the average is now recognisable on sight, which means the average is now expensive — and the only durable answer to that is a face you chose, licensed, for a reason. The week's most interesting physical note came from a printer review: a £1,599 machine and an AI-derived depth map brought back an awards programme that a £15,000 trophy bill had cancelled, which is a useful reminder that "premium" is still often a question of material rather than pixels. **The single highest-leverage move for Shareef this week:** write the platform's catalog — one page naming every component, the states each may occupy, and the tokens each may use, with the 13px table rows, the single accent and the four status colours spelled out — and pair it with one licensed display face for all external creative, so the UI keeps Inter and the posters stop looking generated. Then, if there is a second afternoon, steal Astryx's eval: five tasks, five probes, and grade any agent-built page before a human looks at it.
