### Figma agent — generally available, with per-library guidelines
**Link:** https://help.figma.com/hc/en-us/articles/43509372175511-Add-guidelines-files-to-a-design-library (announcement: https://www.figma.com/blog/3-ways-product-designers-use-the-figma-agent/)
**Type:** Tool
**What it is:** The Figma agent moved from open beta to general availability on October 6, 2026, and the feature that matters is **guidelines**: markdown, plain-text or JSON files uploaded to a *published design library*, which the agent is automatically fed as background context every time someone prompts with that library enabled. Figma recommends 3–8 focused files under 100 KB (cap 200 KB) — `overview.md`, `guidelines.md`, `components.md`, `examples.md`, `anti-patterns.md`, `best-practices.md` — written as scenario-based dos and don'ts with the reasoning attached, prioritising where teams actually get it wrong. The blog pairs it with three named case studies: Uber using agent skills (`/create-anatomy`, `/create-color`) to auto-document components across seven platforms, Granola annotating the canvas from meeting transcripts, and Atlassian turning motion assets into reusable system components so non-motion designers can ship animation inside design-system variables.
**What's good about it:** The architectural decision is the honest one. Figma didn't try to make the model tasteful; it put the rulebook where the model already looks. Guidelines are attached to the *library*, not to a project or a chat thread, so the rules travel with the thing they govern — anyone on the team who prompts with that library gets the constraints for free, and nobody has to remember to paste a brand brief. The content guidance is also unusually good for a vendor doc: it explicitly tells you to document **anti-patterns** and to write "a clear recommendation instead of only describing the available options," and to call out behaviour the agent should never use when there are no exceptions. That is a design director's review brief, not a prompt-engineering tip. The Atlassian quote is the one to steal: *"Being able to generate within guardrails really matters for enterprise systems. It allows for consistency, accessibility, and implementation quality as much as speed."*
**Pros:**
- It converts the design system from a reference into an enforcement surface. The rules are read on every prompt, automatically, which is the difference between a style guide and a constraint.
- `anti-patterns.md` as a first-class file type is the correct primitive — our platform's quality comes as much from what it refuses (no second accent, no gradients, no weight 700 display) as from what it specifies.
- Composable with the things we already decided: this is the same shape as the Markdown design spec we recommended on the 27th and the "design sources" pattern from HappyHands on the 28th. Three independent sources, one format.
- Free-ish to author. It's markdown in a repo. No new tool, no new language, and the writing is the work — which is exactly the work nobody has done.
**Cons:**
- Requires Figma, a published library, and a Professional+ plan. Our production surfaces are a hand-built React platform and a light-theme player; the guidance would describe work that never passes through the canvas, and the agent cannot touch our actual components.
- Nothing here *enforces* anything. Guidelines are context, not a gate — the agent can read `anti-patterns.md` and violate it anyway, and Figma publishes no rejection mechanism. The verification layer is still missing, same as with Specs.
- The quality claim is Figma's own: "~60%+ of our human-graded evals with professional designers," with no published method. Treat as marketing until we run our own.
- Credits now apply, and guidelines *increase* credit consumption per prompt. Also Plan-gated to Professional/Organization/Enterprise with edit access to the file — a governance feature that a single-seat setup can't fully use.
**Should we...**
- ✅ **Adopt it**
**Why:** Adopt the artifact, not the subscription. The most useful sentence in the whole release is the one about documenting anti-patterns, because it names what our platform work has never had written down: the list of things this surface never does. For the Urology Unified Platform that list is short and specific — one accent used sparingly, Inter only in the chrome, no gradient fills, no second display weight, no emoji as iconography, no card radius that wasn't chosen. Right now that knowledge lives in Shareef's head and gets re-explained to every agent session; Figma's contribution is a credible, vendor-endorsed container for it, with a file structure (`guidelines.md`, `anti-patterns.md`, `examples.md`) we can copy this afternoon into the repo next to the code, for zero dollars and no Figma dependency. Where it genuinely fits as a product is if the residency marketing and Sub-I creative ever moves into Figma, which is plausible — those are print-and-social deliverables where a canvas beats a codebase. Where it doesn't: as a substitute for review. This is the third product in eight days to ship "rules as context" while shipping no way to fail an output, and our own gate still has to be the human who can say no.

### Wordsmith AI "Draftboard" — art direction as a tool, built in public
**Link:** https://www.youtube.com/watch?v=m9RovaDXQUw (live tool: https://draftboard-8ac.pages.dev — studio: https://sprintdept.com)
**Type:** Technique
**What it is:** A 7-minute "Behind the Build" from Josh Andrew at Sprint Dept showing how he turned Wordsmith AI's art direction into **Draftboard**, a generative brand tool the client's whole team can use without design skill. The method, in his words: *"The first 30% I need to be heavily involved and actually designing myself because if I can't steer the initial creative direction it's going to be bound to be slop."* He did a brand audit, set the strategy, picked the typefaces and built the first frames in Figma himself, then handed the agent references — screenshots with hex codes, crops of large type vs. small type, a scraped Instagram carousel examined page by page, 8,000px paper textures — alongside three-minute voice notes, and gave it **batched feedback of 10–12 specific notes per version across eight versions: over 90 changes**, until the taste became rules. Output is always typographically coherent by construction, whatever the user's design literacy, and copies straight into Figma components.
**What's good about it:** This is the missing case study for everything we've been arguing about for two weeks, and it's unusually honest about the ratio. The "taste training" framing is precise: he doesn't brief the model, he **shows** it — "look at the large type, look at the contrast in scale, contrast in size, contrast in paper colour, texture layouts" — which is reference-anchored iteration with a human judge, the same loop we praised in napali, applied to print-grade typography instead of a coastline. The batched-feedback discipline (one considered pass of 10–12 notes, not twelve panicked single-line prompts) is what makes eight versions converge rather than drift. And the end state is the thing worth stealing: he built a **constrained generator, not a one-off deliverable** — randomisation is limited to placement, layer, texture and palette within a locked art direction, so volume is safe. That is the correct answer to "we need 40 social cards this month."
**Pros:**
- It makes the human/AI split a design decision with a number attached: 30% human steering, 70% machine production. That's a defensible position to hold in any conversation about what the tool replaces.
- Reference-as-brief beats prompt-as-brief, demonstrated end to end, with the intermediate versions visible — V1 genuinely is "pretty awful," and watching it improve is the argument.
- The output architecture (locked direction, randomised execution) is exactly what residency marketing needs across a season of cards, and it imposes coherence rather than hoping for it.
- Cheap to imitate. No proprietary platform: a coding agent, your own Figma files, your references, and a disciplined feedback loop.
**Cons:**
- The host says "Grok Bot" throughout and the video is titled as such — the naming is muddled and the tooling is a moving target; reproduce the method, not the stack.
- 183 views and 6 likes. This is not a vetted technique with a community stress-testing it, and there is no published failure rate — no account of the versions that didn't converge.
- Eight versions and 90+ notes is real labour. Anyone reading this as "AI makes brand assets fast" has missed that the cost moved into the direction loop, where it isn't cheap.
- The aesthetic landed on "abstract tactile paper-texture legal-tech artifacts" — a house look with identifiable tells. Locking a direction tightly and then generating volume is also how a brand becomes monotonous.
**Should we...**
- ✅ **Adopt it**
**Why:** Because it's the first public account I've seen that puts the honest number on the ratio, and it matches what our own work keeps proving: the front 30% is where quality is won and it cannot be delegated. Concretely for Shareef, this is the blueprint for the residency marketing program — build a constrained card generator whose direction was decided once by a person (one display face, one accent, real faculty photography, a fixed type scale, a locked grid), then let volume come from randomisation *inside* those rails rather than from fresh prompts. It also reframes the season's most repetitive task — dozens of announcement cards, welcome covers and social crops — as a one-time art direction problem with a repeatable machine behind it, which is what an agency would sell. Where it doesn't transfer: do not copy the era-style. The lock once, generate many pattern is only premium if the locked direction was genuinely distinctive; a tightly constrained generator pointed at a generic direction produces perfectly consistent slop, faster.

### GitHub Replica — open-source, design-system-grounded prototyping
**Link:** https://github.blog/changelog/2026-10-28-introducing-replica-an-open-source-ai-prototyping-tool (repo: https://github.com/github/replica)
**Type:** Tool
**What it is:** Open-sourced by **GitHub Design** on October 28, 2026 under MIT. Replica turns ideas into interactive prototypes guided by *your* components, patterns and documentation rather than a generic model's idea of a UI. It ships as four parts: a Starter that scaffolds a local prototype project with agent skills and a working app; a Copilot canvas extension that shows the prototype beside the conversation; an optional self-hosted **Replica Hub** for publishing prototypes and collecting comments; and a build action for Hub publishing. The load-bearing sentence in the announcement: *"Designers define the guidance, while anyone on the team can use natural language in the GitHub Copilot app to create and refine prototypes."*
**What's good about it:** The governance model is stated in the architecture, not the marketing. "Designers define and approve the guidance" is the same division of labour as Figma's guidelines and Wordsmith's 30% — but here it's the *designer* who owns the rules file and everyone else who consumes it, which is the correct power structure for a team where the people generating assets are not designers. Open-source and self-hostable matters more than it sounds: a Hub we control means prototypes of a clinical platform never leave infrastructure we own. And GitHub Design shipping this is a small signal worth noting — the company that owns the code layer has decided prototypes should be grounded in a design system rather than a prompt.
**Pros:**
- MIT, local-first, self-hostable. That's the combination that makes it usable for anything touching patient-adjacent or institutional surfaces.
- The four-part split is sane: guidance authored once, generation with any model, hosting separate, review as comments — each piece replaceable.
- "Your team still decides what should ship and how to build it" is written into the announcement, which is the review posture we want to set as house policy.
- If we're ever prototyping platform flows with Copilot anyway, this is a better substrate than free-form prompting.
**Cons:**
- Copilot-app-dependent. It assumes GitHub Copilot as the generation surface, which is a hard ecosystem commitment for a team not already living there.
- Prototypes, not production. Nothing here reaches the React platform's real components; a prototype grounded in a written guidance file is still a mockup you then rebuild.
- Brand new (announced yesterday), no independent hands-on review, and no evidence on output quality — the announcement makes no quality claim at all, which is at least honest but also unverifiable.
- Adds a fourth place for design truth to live (repo specs, Figma guidelines, guidance file, actual code). Without a single owner, that's drift by design.
**Should we...**
- 👀 **Watch it**
**Why:** The idea is right and the timing is wrong for us. The valuable export today is the framing — design guidance authored and approved by designers, consumed by everyone else, with shipping decisions explicitly reserved to humans — which we can adopt as policy without installing anything. For the Unified Platform, the honest read is that we don't need a prototyping tool; we need the platform's real rules written down once, and Replica would be a fourth copy of them. Where it would earn a second look: if the platform's next set of surfaces gets designed by more than one person, or if a residency/Sub-I microsite ever needs to be explored quickly, a local self-hosted Hub that never sends work anywhere is a genuinely attractive sandbox. Watch it for a quarter, see whether the guidance file format converges with what Figma and GitHub Copilot both published this week, and adopt whichever format wins rather than all three.

### BRND ProType + BRND Grid System
**Link:** https://github.com/brndconsulting/brnd-protype-font (specimen + grids: https://www.brndconsulting.com/post/brnd-protype-grid-system)
**Type:** Tool
**What it is:** Released October 24–25, 2026 by BRND Consulting, a branding agency in Maracaibo, Venezuela that has run 500+ projects since 2013. **BRND ProType** is a neo-grotesque superfamily drawn from scratch: 49 static styles across Condensed, Normal, Extended and Mono, seven weights (Light 300 to Black 900), 21 italics, three variable fonts (weight 300–900 and width 88.1–114.5), 566 characters per style, 57,000+ kerning pairs, OpenType ligatures, fractions and case-sensitive forms — all under SIL Open Font License 1.1, free for commercial use. Released alongside it is the **BRND Grid System**: 644 real-size SVG grids across 14 formats (16:9, 21:9, 9:16, 1:1, 4:5, web at 1152/1248, phone at 390; A4, A3, letter, legal, tabloid, half-sheet, full sheet), 588 modular and 56 original "Tribonacci" grids, under CC BY 4.0. Everything snaps to the **renglón** (baseline unit): gutters are one renglón, margins are one to three, every row is a whole number of renglones, so any text sitting on a row falls on the baseline — 209 of the 588 combinations close the field exactly. Grids ship with `medidas.csv` (columns, rows, margins, gutter, column width, row height, baseline) so they translate straight into CSS Grid.
**What's good about it:** This is a design system released by people who needed it, and the thinking shows in two places. First, the superfamily solves a real problem for a small team: one family with width and weight axes means a poster headline, a body block, a mono data label and an app UI can all be the same voice with different posture — instead of our current default shrug of "system font for everything, Inter for chrome." Second, the grid system is genuinely rare: 209 combinations that close exactly, a single unit governing margin, gutter, row and baseline, and CSV output. Most "grid" downloads are template farms; this one is measured, documented and machine-readable. The low-node-count construction (usable for plotter cutting and embroidery) also signals a studio that thinks past screens. No AI anywhere in it, which is the point — it's the kind of deliberate groundwork that makes every subsequent AI-assisted asset easier to keep on-system.
**Pros:**
- Free, commercial-licensed, 49 styles plus variables — an actual typographic system rather than a single display face bought for one campaign.
- The grids come with numbers in CSV, ready for CSS Grid, with a baseline that every element snaps to. That is discipline you can hand to an agent and an engineer.
- Released by a working branding agency alongside its own tooling — the provenance is craft, not content marketing.
- Versioned with a FONTLOG, a specimen PDF and per-file SHA-256 checksums. Someone is treating it like production software.
**Cons:**
- **Documentation and specimen are in Spanish.** Fine for a human reader, but a real friction for anyone on our team who isn't, and the FAQ is where all the precise rules live (what "exact" vs "adjusted" closure means, what a Tribonacci grid is).
- Neo-grotesque #4,000. It's well-made and completely unspecific — it will read as competent, not as ours. Do not mistake a good free family for a brand decision.
- Release 1.0.2 with 37 stars and one fork: brand new, unproven at text sizes and in long-form print, and no small-caps or tabular-figures detail published in the repo summary.
- 644 grids is a menu, not a system. If we start picking grids per piece we've replaced one default with forty defaults, which is the exact failure mode we keep diagnosing.
**Should we...**
- ✅ **Adopt it**
**Why:** Adopt the grid system immediately and test the type deliberately, because they solve two different problems. The grids address the flaw that makes generated marketing look like a template farm: pieces composed without a shared unit. Taking 4:5, 16:9 and 1:1 grids and *one* phone grid, with their CSVs, and declaring them the residency and Sub-I formats is a decision we can make in an afternoon and then hold every future asset to — a season of announcement cards on a single measured grid reads as a system even when individual cards come from different places. That is the cheapest available upgrade to the marketing work. The typeface is a different judgment: BRND ProType is genuinely useful as a *working* family for draft and internal material, and having a variable family with real widths is a practical asset for fitting a headline to a grid — but it should not become our display voice. If we take anything from the release as brand guidance, it's the principle the grid embodies, and the argument it strengthens: commit to one bespoke display face for campaign work, and let a free superfamily do the utility labour beneath it.

### Mesh Gradient Generation
**Link:** https://github.com/9929y/mesh-gradient-generation
**Type:** Tool
**What it is:** An MIT-licensed agent skill (created October 24, 2026; 63 stars, 4 forks) for producing mesh gradients with real art direction: it decides which colours play which roles, where the main colour masses sit, where text needs safe space, how edges merge, and how the result stays editable — writing native Figma layers (isolated groups with Gaussian-mask soft-enabling and separate colour fills), or SVG via a Python script. Six worked studies at 1536×1024, each documented with its actual construction (blur radii in the 100–200px range, plane opacities at 56–85%, 40-level heightmap contour extraction, eleven Gaussian mask groups), plus palette studies and a written art-direction reference.
**What's good about it:** The craft standard is genuinely high and unusually well-documented for a four-day-old repo — it specifies reconstruction parameters rather than offering a prompt, claims are bounded ("no measured productivity or business-outcome claim is made"), and it requires the agent to hand back node IDs and validation evidence. The reconstruction path is the interesting part: use a reference, unpack how it was built, rebuild it natively so it stays editable. That's the same reference-anchored discipline we keep recommending.
**Pros:**
- Real art-direction logic: palette roles, text-safe zones, composition preserved while colours are compared.
- Native editable output rather than flattened images — the correct deliverable for anything that will be revised.
- Honest about its own gaps, including which layout parameters are still unverified against live Figma.
**Cons:**
- Mesh gradient is close to a definition of the aesthetic we are trying to stop producing. Soft multi-colour drifting fields on a page are the visual signature of 2024–26 AI product marketing, and a better-executed version of it is still that.
- It inflates exactly the thing our platform work deliberately refuses: the Unified Platform's single accent on a flat dark ground is a considered opposite of this.
- Four days old, one machine of testing, and it needs a connected Figma execution tool — the setup is not free.
**Should we...**
- ❌ **Skip it**
**Why:** Skip it as a production method, and be clear about why so we don't relitigate it. The skill is well-made and the underlying craft advice (decide roles, protect the text zone, preserve composition while comparing colour) is sound — but its entire output category is the house style we're escaping. Our premium surfaces earn their quality from restraint and a single accent; mesh gradients earn attention from exactly the opposite, and adding a well-documented generator for them raises our skill level in a direction we don't want to go. The one transferable idea, worth keeping: when a reference is provided, the agent should *unpack how it was built* and rebuild it editably rather than generate something adjacent — that instruction belongs in our own image briefs, regardless of what the image is.

### The AI flyer backlash reaches local press — and the designers' counter-move
**Link:** https://bendbulletin.com/2026/10/28/bend-columnist-for-the-love-of-humanity-please-stop-making-ai-flyers
**Type:** Idea
**What it is:** On October 28, 2026, the Bend Bulletin published a columnist's piece on AI slop flyers, and it's unusually specific: *"AI slop flyers, shouting for your attention in busy typeface and far too many colours, in a style and manner that truly, no human in a healthy state of mind would ever unleash on the world."* It quotes Bend graphic designer Lucy Quade offering small businesses a discounted better solution on Threads, and singer-songwriter/graphic designer Mark Quon, who made a fake AI flyer to parody the form. Quon's framing is the professional's position in one line: *"I compare it to a production artist versus a creative director — you are the creative director, and AI is working for you. They're the production assistant, if you will, and help put things together. But people are just giving it full rein."*
**What's good about it:** It's the moment the "AI flyer" critique stopped being a design-Twitter genre and became civic journalism with a named failure taxonomy. The tells named across the reporting — confusing visual hierarchies, cluttered layouts, overuse of taglines and abstract text boxes, bright colours on black backgrounds, brushstroke fonts with glowing outlines, graphics or text filling every inch — are precisely the slop signals in our brief, and they're being described by members of the public in their own words: "creepy," "oversaturated," "gives me a headache," "takes the soul out of local businesses." The Charlotte Observer reporting went further and documented actual boycotts of businesses that use AI flyers. For anyone producing institutional marketing, that's a reputational risk, not a taste debate.
**Pros:**
- Names the exact compositional failures, in the public's vocabulary, which makes it a pre-flight checklist we can actually enforce on a flyer.
- The "production assistant, not creative director" line is the cleanest articulation of scope we've seen from a working designer this week, and it's quotable to leadership.
- It validates the direction of our platform and premium work from the opposite end: the reason those surfaces read as credible is that every one of the listed tells is absent.
- It's a market opening with a client base already primed — "someone noticed, and can point at why" is a sellable service to any business drowning in its own flyers.
**Cons:**
- Not a tool, not a technique, and there's a real risk of over-learning it into "never use AI imagery," which is as wrong as "always use it."
- Local-news columns are anecdote, not research — no sample, no measurement, and the boycotts described are self-reported.
- The parody-flyer genre is already becoming a cliché of its own; ironic slop is still slop and reads as smug to the audience it's aimed at.
- Zero guidance on the actual craft problem, which is grid, hierarchy and type discipline — the article diagnoses precisely and prescribes nothing.
**Should we...**
- ✅ **Adopt it**
**Why:** Adopt it as the house pre-flight check and as briefing language, because it names the failure in the audience's own voice rather than a designer's. Six questions against any flyer, card or announcement before it ships: is there one clear hierarchy, or is everything shouting? Does any element sit on a grid and a baseline, or was it placed? Are there more than two type sizes doing work? Is there negative space, or does content touch every edge? Is the typeface a choice or a default? Could someone who saw 40 of these this month tell ours apart? If that list feels crude, it's because the tells are crude — and the reporting shows they're legible to people who have never opened a design tool. For the residency and Sub-I materials specifically, where the whole job is credibility with applicants and faculty, "this flyer is clearly AI" is a trust outcome, and the fix is not a better model. It's a grid, one display face, a fixed scale and one accent — the unglamorous decisions this brief keeps returning to.

## Slop Radar
- **"Busy typeface and far too many colours"** — now the public's working definition of an AI flyer, along with bright-on-black, glowing brushstroke fonts and text filling every inch. Any asset that would sit comfortably on a café bulletin board is the wrong asset.
- **Perfectly consistent slop from a locked generator.** The Draftboard pattern is powerful and dangerous: lock a generic direction, generate volume, get forty cards that agree with each other and with nothing else in the category. Coherence is not distinctiveness.
- **Rules-as-context with no gate.** Figma guidelines, Replica's designer-approved guidance and HappyHands all shipped this month; none of them can reject an output. Three products, one missing feature: enforcement.
- **Mesh gradients as "premium."** Well-built tools now exist for the single most overused visual signature in AI product marketing. Better execution of an exhausted form is still that form.
- **The parody-slop genre.** Mock AI flyers and ironic "look how bad this is" posts are becoming their own template. Diagnosing slop in public is not the same skill as making something that isn't.

## Overall Assessment
The week converged on a single idea from four unrelated directions: **the design system is becoming an executable artifact, and the fight has moved from taste to specification.** Figma shipped per-library markdown guidelines that the agent reads on every prompt, with anti-patterns as a first-class file. GitHub Design open-sourced a prototyping tool whose whole architecture is "designers define the guidance, everyone else consumes it." Sprint Dept showed the working version of the same idea at project scale — a human owns the first 30%, converts taste into rules through 90 batched notes, and everything downstream is coherent by construction. And BRND, an actual branding studio, released the substrate: a measured font superfamily and 644 baseline-locked grids with CSVs, so there's finally something to be consistent *to*. Meanwhile the negative proof arrived in local newspapers, where the public described AI flyers using the same failure taxonomy we use internally. The pattern is clear enough to act on: whoever has written down their rules wins, and whoever hasn't gets the default. The single highest-leverage move for Shareef this week is to write the platform's design spec as three short markdown files in the repo — `guidelines.md` (the accent rule, Inter only in chrome, the real type scale), `anti-patterns.md` (the five things this surface never does), `examples.md` (three screens that are right and one that isn't, with a sentence each) — and put them where every agent session reads them before it touches a component. It costs an afternoon, requires no new software, and it is the same artifact Figma, GitHub and every serious studio converged on this month. Everything else on this list is downstream of having it.
