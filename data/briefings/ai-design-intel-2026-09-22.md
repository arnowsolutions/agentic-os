### Boxy (avestura/boxy-design-skill)
**Link:** https://github.com/avestura/boxy-design-skill
**Type:** Tool / Idea
**What it is:** A zero-radius design system for AI coding agents, shipped as an installable skill (`/plugin marketplace add avestura/boxy-design-skill`). Seven axioms govern everything: radius is zero everywhere (including avatars and toggles), 1px lines carry structure, blurred shadows are forbidden, everything snaps to a 4px scale, accent is rationed under 5% of painted pixels, hierarchy is typographic, and motion is mechanical (80–160ms, no scale, no bounce). Three modes — blueprint, industrial, editorial — change only section rhythm, display scale, grid columns and substrate. The enforcing half is `boxy-check`: a dependency-free Node ≥18 linter that parses CSS, HTML, JSX, Vue and Svelte, flags every violation with file and line, and exits non-zero. Ships 13 reference docs, a W3C DTCG token export, and writes configs for Claude Code, Cursor, Windsurf, Copilot and AGENTS.md targets at once. MIT, created Sept 20.
**What's good about it:** This is the sharpest articulation of the actual anti-slop architecture I have seen this month, because it names the real failure mode in its own README: *"Most design guidance is advisory, so agents drift back to rounded cards and soft shadows by the third prompt."* Boxy answers that with exactly one mechanism — constraints plus a linter — and then audits against them on every run. The axioms are opinionated in the way a studio is opinionated, not in the way a template is: rationing accent to under 5% of painted pixels and forcing hierarchy through type rather than color are senior typographic positions. The before/after table is genuinely honest about what it is replacing (14px radius, pill buttons, 8px blurred drop shadow, "violet gradient doing the work of hierarchy"). The linter's rule set is also well-chosen from a craft standpoint: `transition: all`, durations over 240ms, `backdrop-filter`, gradient-clipped text, `ease-in-out` and overshoot curves all fail as errors — those are precisely the motion and surface tells that read as machine-made.
**Pros:**
- Ships the enforcement, not just the guidance — `npx boxy-design check "src/**/*"` fails the build, which is the only thing that reliably holds an agent to a visual system
- The axioms are specific enough to be argued with and defended: zero radius everywhere, no blurred shadow, sub-5% accent, 4px scale, 80–160ms mechanical motion
- Multi-agent targeting out of the box — one install writes `.claude/skills/`, `.cursor/rules/`, `.windsurf/rules/`, `AGENTS.md` and `.github/copilot-instructions.md`, so every harness reads one source of truth
- Three named modes with identical fundamentals is a genuinely intelligent way to span dev tools, admin dashboards and marketing pages without inventing a second system
**Cons:**
- One star and one day old — created Sept 20, pushed Sept 21. Treat the *pattern* as adoptable today; the repo as unproven
- The zero-radius, no-blur, no-scale aesthetic is a strong house style, not a neutral system. It is the opposite of the Urology Platform's current surface language and cannot be applied there wholesale
- The linter is a static parser; it catches `border-radius: 8px` but cannot judge whether the page reads as designed. Enforcement covers the measurable half only
- Committing to it means committing to square corners across a whole project, which is a brand decision, not a tooling decision
**Should we...**
- ✅ **Adopt it** — use it now; it raises our design ceiling
**Why:** Boxy matters to Shareef on two levels, and the second one is the real prize. The first is literal: for any new premium client-style website build — a marketing surface where a distinctive, engineered, square-edged direction would actually suit the brand — Boxy is a ready-made art direction with teeth, and its `editorial` mode (big display type, 160px rhythm, generous air, still perfectly square) is a credible premium marketing posture that is visibly *not* the default AI landing page. The second is the transferable pattern, which is worth more than the tool: Boxy demonstrates that a design system can be expressed as axioms an agent cannot silently violate, with a checker that exits non-zero. That is the exact shape of the guardrail the Unified Platform needs — not "prefer the design tokens" in a README, but a script that fails on a hex literal outside the token file, an accent outside Montefiore navy #003da5, spacing off the scale, or inconsistent icon stroke weight. `boxy-check`'s rule list is a better starting spec for that script than anything we could write from scratch, and the `raw-hex` and `space-off-scale` warnings are precisely the drift we want to catch. Adopt Boxy's *method* into the Unified Platform pre-flight immediately; evaluate Boxy itself as a direction for the next client-style site build where a hard-edged system is the right answer.

### Editorial Web Craft
**Link:** https://github.com/fernandokylas/editorial-web-craft
**Type:** Tool / Workflow
**What it is:** A set of twenty composable design skills plus a `web-craft` orchestrator (v1.0.0, released Sept 17) for building web interfaces that read as print-grade — "the way a consultancy ledger, a financial journal, or a well-set book feels." Installs as a Claude Code plugin, through the open skills CLI (`npx skills add fernandokylas/editorial-web-craft`) for any agent, or as a `.skill` file for Claude.ai. The orchestrator classifies a brief on five axes (reading/grid/deck/mixed, paper/obsidian/mixed, motion budget, network budget, new vs. improve), loads only the skills that apply, builds from a self-contained boilerplate, runs `python3 skills/web-craft/scripts/audit.py page.html`, then previews at three widths in Chrome DevTools under `prefers-reduced-motion` before judging hierarchy, rag and optical alignment by eye. Seven checkers, merged output, exit 1 on any FAIL.
**What's good about it:** The individual skills are the most typographically literate thing I have reviewed in weeks, and they are written the way a senior designer actually thinks. `layout-editorial-rail` establishes the signature layout as a narrow meta rail beside a copy column capped at 62ch — a real editorial decision with a real reason (it replaces full-width text and centred containers). `fluid-clamp-calculator` derives exact `clamp(min, calc(a rem + b vw), max)` values so endpoints land precisely between 320px and 1440px, with rem caps that survive browser zoom. `typographic-rag-tuner` covers `text-wrap: balance` on headings and `pretty` on prose *and* the things those can't do — keeping `Q3 2026` and `12 %` from breaking, hyphenating long words, reading a rag. `visual-weight-tuner` is a seventeen-item reference of optical corrections (icons nudged to cap height instead of flexbox's line box, circles scaled 10–15% so they match squares, buttons given a hair more bottom padding) — this is the uncodified knowledge that separates a designer from a layout generator. And `accessible-ink-scale` encodes the fact that small text loses its strokes: step up a weight below 14px, open tracking below 13px, 0.08–0.12em on uppercase, never pure white on dark. The `ground-inversion-guard` skill handles the thing almost everything else gets wrong — that an accent *changes role* when a section flips from paper to obsidian (a deep green fill becomes a bright mint text color), with a paired token contract and every pair measured, nothing shipped under 7:1.
**Pros:**
- Genuinely deep typographic craft, not vibe guidance — rag control, fluid clamp math, optical weight correction, micro-type ink compensation, ground inversion, all with bundled scripts that generate or verify
- Verification is built in: seven checkers with exit-code failures, fixture tests pinning what each checker must catch, CI-enforced on every push, and a DevTools preview protocol that judges what scripts cannot see
- Ships across four environments (Claude Code plugin, skills CLI, Claude.ai `.skill`, your own marketplace), MIT, with no package manager, build step or network requirement
- The orchestrator's honesty discipline is a model: on an existing page it audits and previews *first* and reports what was wrong before changing anything, and it never claims a preview it did not run
**Cons:**
- Two stars, single author, and a v1.0.0 published five days ago — early, though unusually well-engineered for its age
- Web-interface shaped only: no help with social creative, print collateral, or the residency marketing image assets
- The DevTools preview path assumes Node and Chrome; without a browser it degrades to static audit plus checklist
- Twenty skills is a real reading commitment before you get value, and the aesthetic it encodes (display serif over quiet sans, editorial rail, obsidian/paper grounds) is a specific direction, not a neutral toolkit
**Should we...**
- ✅ **Adopt it** — use it now; it raises our design ceiling
**Why:** Two of Shareef's surfaces are typographic problems before they are anything else, and Editorial Web Craft attacks exactly that. The first is the Big Reef Chapter Player: a polished light-theme reading surface is a *typography* product, and the skills that matter there — rag control, 62ch measure, micro-type ink compensation below 14px, the accessibility floors — are the difference between a reader that feels typeset and one that feels like a web app. The second is the premium client-style website work, where `layout-editorial-rail` plus the paper/obsidian ground system plus the 7:1 contrast discipline produces pages that read as designed by someone who sets type, not assembled by someone who picks components. Two specific transfers worth making this week regardless of whether we install the plugin: (1) the `ground-inversion-guard` concept applies directly to the Unified Platform's dark surfaces — our accent has a *role* on dark that differs from its role on the light marketing pages, and encoding that as a paired token contract with measured contrast would eliminate a whole class of contrast bug; (2) `accessible-ink-scale` gives us a pre-ship gate for the Sub-I welcome materials and residency marketing, where small uppercase labels on light grounds are exactly where legibility quietly fails. Adopt the skill set for web builds, and adopt the audit discipline — measure it, don't eyeball it — everywhere else.

### Design Slop Cop
**Link:** https://github.com/AdrianKrebs/design-slop-cop (live: https://slopcop.adriankrebs.ch — the live host was unreachable from this VPS at scan time, HTTP 000; the GitHub repo and the blog post both resolved cleanly)
**Type:** Tool
**What it is:** A free tool that scores any website 0–100 for how AI-generated its design looks plus a browsable report corpus. A headless browser (Playwright) loads the page, an in-page script walks the live DOM and reads computed styles, and each of 14 deterministic CSS/DOM patterns is checked and flagged with evidence. Patterns include templated display fonts used as the page default (Space Grotesk, Instrument Serif, Geist, Syne, Fraunces), hero font mix, "vibe purple" indigo/violet CTAs, gradients and gradient-clipped text, accent stripes on card edges, glassmorphism, colored glow shadow, fake dark mode (muted grey body text on dark), numbered 1·2·3 step rows, stat banners, headline badges, icon-card grids, and FAQ accordions. Scoring is transparent: `score = round(100 × patternsFlagged / patternsTotal)`, tiered High/Medium/Low/Clean. Outputs JSON for batch runs. MIT.
**What's good about it:** This is the anti-slop instrument we have been assembling by hand, except it is quantified, repeatable empirical data rather than a hunch. Two design choices make it trustworthy in a way most AI-detectors are not. First, it deliberately does **not** screenshot the page and ask an LLM to judge it — every pattern is a deterministic CSS or DOM query, so the result is explainable and identical on re-run, and there is a readable rule per pattern in `src/patterns/<id>.js` that a designer can argue with. Second, it ships its own ground-truth discipline: 165 labeled sites, a labeling UI, and an `npm run eval` precision/recall harness, with the author reporting ~5–10% false positives on ~150 manually verified sites and inviting you to take it "with a grain of salt." The pattern list itself is a genuinely useful design vocabulary — the finding that *colored left borders are almost as reliable a sign of AI-generated design as em-dashes are for text* is the kind of sharp, specific tell worth internalizing. The batch corpus run over ~1,400 Show HN submissions (53% triggered at least two patterns; one in five triggered four or more; fake dark mode the most common at 34.7%) is real measured data about where generic design actually sits.
**Pros:**
- Deterministic, explainable scoring with no LLM judgment in the loop — same page in, same score out, with the evidence attached to each flag
- Ships its own accuracy discipline: 165 labeled sites, a labeling UI, an eval script, and an honest published false-positive rate rather than a claim of authority
- The 14-pattern list is immediately useful as a written review vocabulary even if we never run the tool
- Free, MIT, JSON output for batch runs, a browsable tier-filtered report corpus, and a per-pattern reference explaining why each signal exists
**Cons:**
- The rule set is calibrated to the *landing page* archetype. It will score a dense admin dashboard, an editorial site, or a deliberately styled dark product surface poorly for reasons that are not slop
- "Perma dark" and "glassmorphism" are flagged as tells, which is wrong for Shareef specifically — a premium dark UI with intentional glass is a deliberate design decision, not a default
- The live host was unreachable from this VPS during the scan window (HTTP 000 on both https and the blog-linked host); the repo works and runs locally via `npm start`, so treat the hosted version as a convenience, not a dependency
- The repo itself is from late April, last pushed July — the *tools* are current and it surfaced fresh in this week's HN/aggregator scan, but this is not a new release
**Should we...**
- ✅ **Adopt it** — use it now; it raises our design ceiling
**Why:** Adopt this as the baseline measurable gate on every marketing and client-facing surface Shareef ships, and adopt its pattern list as a *design* artifact today. The concrete use: run the residency program marketing pages, the Sub-I welcome materials' web components, and any premium client-style website through it before they go out, and treat a High score as a stop-and-look signal. But the more valuable application is the inverse — take the 14 patterns and turn them into a written prohibition list for our own agent prompts, so we stop producing them in the first place. Two of the flags deserve explicit disagreement and that disagreement is the point: "perma dark" and "glassmorphism" are only tells when they are *defaults*. The Urology Unified Platform is a deliberate premium dark surface with a single accent, and the question we should be asking is not "is dark slop?" — it is "is our dark a decision with a system behind it, or did we land here because every model reaches for dark?" Design Slop Cop is the instrument that lets us answer that with a number instead of an opinion, and its honest 5–10% false-positive rate means we use it as a prompt for review, never as an automatic verdict. Pair it with the previously-adopted design-rules file: that tells the agent what to avoid, this tells us whether it obeyed.

### DESIGN.md Generator
**Link:** https://github.com/Vann4799/design-md-generator
**Type:** Tool / Workflow
**What it is:** A skill that writes a locked `DESIGN.md` design system and then validates and exports it. It extracts a direction through one of three paths — a short interview (three rounds of at most four questions), a brand guide or reference site you point it at, or, only if you refuse both, a proposed direction stated plainly as a proposal. It writes `DESIGN.md` with a CSS `:root` block as the source of truth, ten fixed sections, and a written reason for each of seven decision groups. The steering mechanism is a single `Design Read` line: `Dial: ENERGY 2 / RHYTHM 3 / MOTION 2` — same file, three numbers, different output. It then runs `validate_design.mjs` until every FAIL is gone and exports to `tokens.css`, a Tailwind v4 `@theme` block, W3C DTCG `tokens.json`, and shadcn/ui CSS variables. Works with Claude Code, Codex, OpenCode, Qoder CLI, and — notably — Hermes Agent. MIT, created Sept 20.
**What's good about it:** The thesis is the strongest sentence in this week's entire scan, and it is a direct rebuke of the current anti-slop wave: *"a filter can remove AI slop but it cannot add identity. Bare anti-slop rules leave you with a beige, card-less, gradient-free page that looks like every other safe output."* That is exactly right, and it is the trap the other five items in this brief are each half-exposed to. Removing purple gradients and rounded corners does not produce a point of view. DESIGN.md Generator's answer is to make the *choice* explicit and durable: pick a direction on purpose, write down the reason for it, validate it, and lock it so the system "stops diversifying and starts being obeyed." The validator is the enforcement: it checks the ten required sections and their order, the dials against frontmatter, leftover placeholders, a written reason for each decision group, and measures ink/paper, secondary text, accent label and focus contrast against WCAG 2.1 — doing the OKLCH → OKLab → linear-light sRGB conversion properly and compositing alpha the way a browser actually paints it. It exits non-zero, so it drops into CI or a pre-commit hook. Two more details show unusual judgment: the exporter "never invents a dark palette — a dark mode is a separate decision, not an inversion," and the skill refuses to call an undesigned system "locked," writing `Status: draft without direction` at dials 1/1/1 and telling you the result is not shippable.
**Pros:**
- Correctly identifies the failure mode the rest of the anti-slop wave creates — subtraction without a point of view — and fixes it by forcing an explicit direction with a written rationale
- Machine-enforced: validator exits non-zero on missing sections, placeholders, absent reasons, or failing contrast, wired for CI and pre-commit
- Real token interoperability — `tokens.css`, Tailwind v4 `@theme`, W3C DTCG JSON, and shadcn vars from one locked source, so the system has teeth on day one instead of sitting beside hard-coded hex
- Honest by construction: refuses to call an undesigned system "locked," declines to auto-generate a dark palette, and states when it had to fill in variables itself
- Installs into Hermes Agent directly (`hermes skills add …`) — it fits our stack without translation
**Cons:**
- One star, two days old, single author. The interview quality is the whole product and it is completely unproven
- The three-round interview is friction by design; used carelessly it becomes a form to click through rather than a design conversation
- Requires the *designer* to have a direction worth encoding. If the brief is vague, a locked wrong system simply locks faster
- The `slop-tells.md` dose-cap model is inherited from upstream projects (hallmark, anti-slop) and its thresholds are not independently validated
**Should we...**
- ✅ **Adopt it** — use it now; it raises our design ceiling
**Why:** This is the missing half of everything else in this brief, and the argument lands hardest for the Unified Platform. We already have rules about what agents must not do — the design-rules file, the lint pattern from Sept 21, the icon and token discipline. What we do not have is a single locked, validated, written statement of what the Unified Platform *is*: which dials are set, what the type scale relationship is, how the ground layering works, why the accent is rationed the way it is, what the motion timing is and why. DESIGN.md Generator produces exactly that artifact, and the reason-for-every-decision requirement is the mechanism that turns a token file into a defensible system. Concretely: run it against the Unified Platform's existing surface, lock the system, export to the token formats, and wire the validator into the pre-flight so no agent-authored component can drift from it. The "never invent a dark palette — dark mode is a separate decision, not an inversion" rule is worth adopting as policy on its own, because inverting a light system to make a dark one is precisely how you get the "fake dark mode" tell that Design Slop Cop flags at 34.7% frequency. And the skill's central insight should govern how we use every other item in this brief: our goal is not a slop-free page, it is a page with a point of view that we can defend and reproduce. Subtracting slop gets us to beige. Locking a direction gets us to a brand.

### Beautify Site
**Link:** https://github.com/beautify-site/beautify-site
**Type:** Tool / Workflow
**What it is:** A Claude Code skill (also bundled into the Omniscio desktop app, v0.1.105+) that reorganizes a redesign the way a designer actually works. It enforces a fixed order: settle one bold visual direction and save it as `design-system/<slug>/MASTER.md` (the contract every later step follows), name at least six visual devices before building anything, then find free components on 21st.dev and restyle them to that system or hand-build them, then add purposeful motion with Motion within a scroll budget and full reduced-motion support, then run a mandatory AI-tell pass that strips giveaways such as gradient text, side-stripe accents, eyebrow labels and fake terminal mockups. It verifies contrast, keyboard access, reduced motion and mobile overflow, screenshots the rendered page, and never spends money on generation without explicit approval. MIT, created Sept 16.
**What's good about it:** The prevention logic is correct and it is stated as a principle: *"Choosing components before the design system exists is exactly the failure this skill is built to prevent."* That single sentence names why so much AI-assisted redesign fails — the model reaches for the nearest good-looking component library and then tries to reconcile five unrelated visual languages afterwards, which is why the result reads as "nice-looking parts that don't belong together." Enforcing direction → density → components → motion → audit fixes the sequence. The visual-density gate is a smart inversion too: requiring at least six named visual devices *before* building is an explicit defence against the tasteful-but-empty page, which is the other failure mode of competent AI design. And the mandatory AI-tell pass is specific rather than vague — gradient text, side-stripe accents, eyebrow labels and fake terminal mockups are named, checkable targets, consistent with the tells we catalogued on Sept 19. Full reduced-motion support and a scroll budget for pinned sections show motion is treated as a cost, not a free decoration.
**Pros:**
- Enforces the correct design sequence (direction before components) as a hard rule of the pipeline rather than a suggestion in a prompt
- The visual-density gate names a required number of devices before building — a direct countermeasure to the tasteful-but-empty failure mode
- Its AI-tell blocklist is concrete and current: gradient text, side-stripe accents, eyebrow labels, fake terminal mockups
- Verifies rather than asserts — contrast, keyboard access, reduced motion, mobile overflow checked, then the rendered page screenshotted
**Cons:**
- Seven stars, six days old, four commits, built by a company as a feature magnet for its desktop app (Omniscio) — the repo is a distribution channel as much as a tool
- Heavily coupled to React + Tailwind at full strength; Vue, Svelte, Astro and plain JS get direction and motion only, with components hand-built
- Its best helpers are optional third-party skills (Impeccable, ui-ux-pro-max) — the strong version depends on installing three things, not one
- "Bold by default" and "always searches 21st.dev for components" push toward a house look of its own, which is a different flavor of the same problem if left unexamined
**Should we...**
- 👀 **Watch it** — promising, not proven yet
**Why:** Watch the repo; adopt its *sequence* this week. The reason it is a watch rather than an adopt is not the quality of the thinking — the thinking is right, and its "direction before components" rule plus the visual-density gate are the two best process ideas in this brief. It is the dependencies and the provenance. Beautify Site is a five-day-old skill with seven stars, it is built by Omniscio partly to sell Omniscio, and its strongest capabilities lean on two other third-party skills. For the Unified Platform — a production system where unapproved design changes are genuinely destructive — that is not a dependency to introduce yet. What transfers immediately and safely is the pipeline: settle the direction and write it to a durable contract before anything is chosen, require a minimum inventory of visual devices before building, and run a named AI-tell pass as a mandatory final step rather than an optional polish. That sequence is compatible with the tighter, verifiable architectures above (Boxy's axioms, DESIGN.md's locked system, Editorial Web Craft's audits) and it is the right shape for agent-assisted redesign work on the marketing and client sites, where a page that reads as "parts that don't belong together" is exactly the failure we are trying to leave behind. Give it a month and a few hundred stars, then re-evaluate.

### Inkloom
**Link:** https://github.com/Inkloom-art/inkloom (product: https://inkloom.art)
**Type:** Idea
**What it is:** A research direction — and an auditable public codebase — for AI models that construct logos the way a studio does, as a sequence of explainable decisions rather than a sampled image. Four declared stages: **brand analysis** turns a business description (sector, audience, tone, competitors) into concrete constraints — stroke weight, width, geometry, counter shape, which symbol families fit; **typography** selects and fits letterforms against those constraints, then does the work that makes a wordmark (optical spacing, kerning at display size, a custom ligature where the name needs one); **symbol construction** composes geometric primitives under construction rules (shared radii, tangent junctions, consistent terminals); **composition** applies optical rather than mathematical centring, derives clear-space ratios from the mark's own geometry, and produces the lockup variants a brand actually needs. The stated output is a *specification, not a bitmap*. Generation is not live — the repo says so plainly on every page.
**What's good about it:** The thesis is the most useful thing here and it is precisely the distinction that separates a logo from AI slop: *"A logo is not a picture. It is a constructed object with rules: a mark that holds at sixteen pixels and on the side of a building, letterforms spaced by eye rather than by metric, clear space derived from the mark's own geometry, and lockups that still read when one of them is all you have room for."* That paragraph is a better brief for logo work than anything a prompt can express, and it correctly diagnoses why general image models fail at logos — they produce "something logo-shaped — a plausible arrangement of marks with no construction behind it, no reasoning about the business, and nothing you can hand to a printer." The engineering candour is genuinely unusual and it is the reason this earns a line: the README states that generation is not live, that credits are *reserved* rather than spendable, and that the feature flags which would enable generation default to off and are deliberately not toggleable from the console, "because enabling a flag whose feature does not exist exposes a broken surface rather than a feature." The test discipline matches the claims — the suite runs against a real database, a real browser and a real mail server rather than mocks, and the load-bearing test fires twenty-five simultaneous redemptions of one access code and asserts exactly one redemption, one ledger entry, one balance survive.
**Pros:**
- The stage decomposition (brand analysis → typography → symbol → composition) is a genuinely sound model of professional identity work, and the clear-space-derives-from-the-mark rule is a real craft principle
- Reframes the output as a specification rather than an image, which is what makes a logo defensible, reproducible and hand-off-able to a printer or sign maker
- Exceptional operational honesty: states plainly that generation is not live, that credits are reserved not spendable, and that feature flags stay off until the feature exists
- Public source for auditability, with a real-database/real-browser/real-mail-server test suite rather than mocks
**Cons:**
- Generation does not exist yet. This is a platform and a thesis, not a usable logo tool — you cannot make a mark with it today
- Twenty stars, created Sept 20, single organisation; the timeline for generation, export formats and brand kits is unspecified
- Logo design is the surface where AI substitution is least welcome and the licensing/trademark exposure is highest — the graphic_design threads this week were blunt that the trademark angle bites first
- Not published as a usable distribution (all rights reserved, not for reuse), so it is reading material, not infrastructure
**Should we...**
- 👀 **Watch it** — promising, not proven yet
**Why:** Watch it, and steal the brief today. Inkloom is not something Shareef can use — generation is not live and the timeline is open — but it is the clearest public articulation this week of *why* identity work resists AI substitution, and that framing is immediately useful. The residency program's marks, the Sub-I welcome materials' visual identity, and any Big Reef branding work all benefit from the test its four stages imply: does the mark hold at 16px and at building scale? Are the letterforms spaced by eye rather than by metric? Is the clear space derived from the mark's own geometry rather than an arbitrary padding token? Do the lockups still read when only one fits? Those are the questions that separate a designed identity from a generated one, and they are checkable by a human in a review without any tooling at all. Equally important is what this find says about where *not* to point generation: the graphic_design discussion this week was pointed about the exposure profile — purely AI-generated output without human authorship is not eligible for copyright (citing the DC Circuit ruling left standing when the Supreme Court declined Thaler v. Perlmutter in March), and trademark invalidation is the angle most likely to bite first. For a residency program and a department brand, that is a real risk, not a theoretical one. Use Inkloom's decomposition as our logo brief and its constraint framing as the input to our prompt architecture; keep human authorship firmly in the loop on anything that functions as a mark of identity. Revisit the repo when generation actually ships.

## Slop Radar
- **Design skills exploding as a genre with no quality filter** — `design skill ai created:>2026-09-15` returned dozens of one-star repos in a week: `apple-ui-design`, `y2k-design-skill`, `design-director`, `design-direction`, `anti-slop-design`, `jbelly-ui`, `design-base-skill`. Many are a directory of copied text and a dial system. A skill is not a design system; it is a prompt with a folder icon. Judge the ones that ship a **verifier**.
- **Subtraction mistaken for taste** — the anti-slop wave's failure mode, now named outright by DESIGN.md Generator: strip the gradients, the rounded corners and the purple, and you are left with "a beige, card-less, gradient-free page that looks like every other safe output." Slop-free is not the same as designed. The page still needs a point of view.
- **Aesthetic-as-a-pack: named era and named-style presets** — the new crop of skills ships "chrome, gel, Aqua, cyber-pop," "Apple-inspired," "Swiss," and "brutalist" as selectable options. A preset is a mood, not a system, and picking one off a shelf reproduces the template-farm problem with better typography. Constraint is not the same as costume.
- **Cracked-software and API-gateway repos still wearing a design label** — this week's GitHub results again included AutoCAD-Cracked, Illustrator-Cracked and CorelDRAW-Cracked listings plus a cluster of `apimart-*` gateway repos (Grok Image, Nano Banana Pro, Midjourney pricing) created by near-identical accounts. Zero craft content; malware and reseller SEO respectively. Ignore entirely.
- **"AI design director" prompt threads** — the recurring X format that opens "Act as my Design Director and build a complete visual identity for my brand." It produces a mood board with a hex palette, not a system that survives a second surface, an accessibility requirement, or a print hand-off.
- **Benchmarks and detectors judged by the model being judged** — any design evaluation the generating agent can see measures compliance, not quality. This is the one thing Design Slop Cop gets right by refusing to screenshot and ask an LLM to score.

## Overall Assessment
Six finds, and the shape of the field is unmistakable: **the industry has stopped asking for good design and started building systems that make bad design fail the build.** Boxy writes seven design axioms and ships a linter that exits non-zero on a rounded corner. Editorial Web Craft ships twenty craft skills backed by seven audit checkers, fixture tests and CI. DESIGN.md Generator locks a validated design system with WCAG-checked tokens and refuses to call an undesigned system locked. Design Slop Cop scores any live page against 14 deterministic tells with the evidence attached, and publishes its own false-positive rate. Even Beautify Site, the weakest of the six, earns its place on a single principle — direction must exist before components are chosen. This is a genuine maturation away from prompt poetry, and it is the right direction for a department that wants agency-grade output. But the sharpest sentence in this week's scan is the warning attached to that same movement, and it comes from DESIGN.md Generator: **a filter can remove slop but it cannot add identity.** Every one of these tools can get Shareef to a clean, restrained, defensible page. None of them can decide what the page is *for* or what it should feel like. That decision is the design director's, and it is not automatable — which is precisely why the tools are worth adopting and nothing more than that. **The single highest-leverage move for Shareef this week:** lock the Unified Platform into a written, validated design system — a `DESIGN.md` with explicit dials, a token block, a reason recorded for every decision — and wire its validator plus a Boxy-style rule check into the pre-flight for any agent-authored UI. We already tell agents what to avoid; this week we write down what the platform *is*, make it machine-checkable, and stop re-litigating the visual system on every task. Pair it with Design Slop Cop as the outward-facing check on marketing and client surfaces: one gate for our own system, one measurement for anything that ships to an audience. Everything else on this list is a better tool. Those two are a standard.
