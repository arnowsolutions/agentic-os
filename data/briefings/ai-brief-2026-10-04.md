### Google ADK 2.0

**What it is:** Google ADK 2.0 is a major agent framework from Google, announced and updated at Google I/O 2026. With its shift from a hierarchical executor to a graph-based execution engine (conceptually similar to LangGraph), ADK 2.0 supports sophisticated multi-agent orchestration including coordinator agents, sub-agent delegation, and fan-out/fan-in patterns. It ships with built-in human-in-the-loop primitives and state persistence, making it production-ready out of the box.

**Source:** https://google.github.io/adk-docs/  ·  [Provenance: web search]

**What's good about it:** Google's Agent Development Kit provides a comprehensive framework for building AI agents with sophisticated orchestration capabilities, built-in safety features, and tight integration with Google Cloud services.

**Pros:**
- Backed by Google ensuring long-term support and resources
- Graph-based execution enables complex agent workflows
- Built-in human-in-the-loop primitives for safety
- State persistence for reliable long-running agents
- Part of broader Google ecosystem including Managed Agents API and Agent2Agent protocol
- Apache 2.0 licensed for permissive use

**Cons:**
- Strong tie to Google Cloud may create vendor lock-in
- May be overkill for simpler agent use cases
- Learning curve associated with new framework
- Limited real-world deployment evidence as it's quite new (I/O 2026)

**Should we...**
- 👀 **Watch it** — keep an eye on it, not ready yet but promising

**Impact on our stack:** High — Could significantly enhance our agentic-os and Hermes cron capabilities for building sophisticated AI workflows

**Why:** Google ADK 2.0 represents a major advancement in agent frameworks with production-ready features like state persistence and human-in-the-loop controls. For our agentic-os stack, this could provide a more robust foundation for building complex AI workflows than our current custom solutions. The graph-based execution model is particularly powerful for orchestrating multi-step agent processes. However, given our existing investments in the Agentic OS stack and the Google-centric nature of this framework, we should watch its development and community adoption before considering migration or integration.

**What it is:** OpenAI Agents SDK - Handoffs or agents-as-tools

**Source:** https://github.com/openai/openai-agents-python  ·  [Provenance: web search]

**What's good about it:** The OpenAI Agents SDK provides an official framework from OpenAI for building AI agents with capabilities for handoffs between agents and treating agents as tools that can be used by other agents or systems.

**Pros:**

- Agents-as-tools pattern enables modular agent design
- Handoff capabilities facilitate complex multi-agent workflows
- Python and TypeScript support covers major development languages
- MIT licensed for permissive use

**Cons:**
- Tightly coupled to OpenAI ecosystem limiting model flexibility
- May duplicate functionality we already have in our Agentic OS stack
- As a relatively new offering (2026), long-term stability is unproven
- Potential overlap with existing agent frameworks creating confusion

**Should we...**
- 👀 **Watch it** — keep an eye on it, not ready yet but promising

**Impact on our stack:** High — Could enhance our agentic-os by providing standardized patterns for agent composition and tool usage

**Why:** The OpenAI Agents SDK introduces valuable patterns particularly around the "agents-as-tools" concept which aligns well with modular agent design principles. For our Agentic OS stack, this could provide standardized approaches to agent composition that improve interoperability and reusability. However, given our existing agent framework investments and the SDK's OpenAI-centric nature, we should evaluate it carefully against our current architecture before considering adoption. The handoff capabilities are especially interesting for building sophisticated multi-agent systems.
